# F097 log

## 2026-11-18: bug added (/bug, human-led)

What was seen:
- main's CI `e2e (3)` went red on every run of 2026-11-17 (44042786773, 44043562143, 44052370140, 44053412030,
  44104805508). Each time the one failure was `e2e/F081-cover-upload.spec.ts:72` ('a refused replacement keeps the
  current cover'), `toHaveScreenshot(F081-cover-upload.png)`, about 34 pixels (ratio 0.01) different.
- Between F094 (#225, green on 2026-11-16) and those runs, only harness-kit upgrades merged. They changed no app
  code, spec or e2e config. The run on 2026-11-18 (44250557542, #227) is green with the same app code.
- Cause: the spec adds its book as Reading, so the `books_set_started_on` trigger sets `started_on` to today (UTC),
  and the page shows 'Started on <today>'. The screenshot masks `page.locator("time")`, but the mask box takes
  the date's text width, so a day whose date renders wider or narrower than the baseline's moves the mask and
  fails the comparison. F078 fixed the same thing for F064 and F065 by masking the whole block. F081's spec,
  written later in M8, went back to masking only `<time>`.

Reproduced in a cloud session on 2026-11-18. With the local DB trigger replaced so that started_on =
'2026-11-17', `scripts/e2e.sh e2e/F081-cover-upload.spec.ts --grep 'refused replacement'` failed with
`34 pixels (ratio 0.01 of all image pixels) are different`. With the original trigger (today = 2026-11-18) the
same test passed. Of the other screenshots that mask `time` only, F066's tag-empty page shows no dates, and
F064 already masks whole rows.

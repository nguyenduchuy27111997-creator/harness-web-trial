# Design M2: book page with status, rating, review and delete; status filter tabs; yearly stats; 404s

Builds on `docs/design/M1.md`: everything there (clients, `requireUser()`, form shapes, guards, module rules) stays. Product choices are in `docs/decisions/0002-product-choices.md`.

## Features
- F009 Book page: `getBook` (M1 columns only, returns `Book | null`), `isUuid`, route `/books/[id]` (heading, author, status badge, "Back to my books"); list titles link to it. No migration.
- F010 Status change: migration 1 (finish date, rating and review columns, finish-date trigger, update policy, column grants); `updateStatus` action, `updateBookStatus`, `formatFinishDate`; widens `getBook` to select the three new columns and return `BookDetail | null`; "Finished on <date>" on the page.
- F011 Rating: `saveRating` action, `parseRating`, `updateBookRating`; 5-star control (shadcn `radio-group`) shown only while Finished. Uses migration 1.
- F012 Review: `saveReview` action, `parseReview`, `updateBookReview`; review field shown only while Finished. Uses migration 1.
- F013 Filter tabs: `parseStatusFilter`, `listBooks(supabase, status?)`; tab links on `/books`; "No books here" empty tab. No migration.
- F014 Delete: migration 2 (delete policy); `deleteBook` action and `removeBook`; confirm dialog (shadcn `alert-dialog`).
- F015 Stats: `getStats`, `summarizeStats`, `formatAverage`; route `/stats`; header links to `/books` and `/stats`. Uses migration 1.
- F016 Not found: `app/books/[id]/not-found.tsx`; the page calls `notFound()` when `getBook` returns `null`. No migration.

## Data model
`public.books` gains three nullable columns (all M1 columns, checks, index and policies stay):

| column | type | rules |
|---|---|---|
| `finished_on` | `date` | null; set only by the trigger below |
| `rating` | `smallint` | null, `check (rating between 1 and 5)` |
| `review` | `text` | null, `check (char_length(review) <= 2000)` |

- Trigger `books_set_finished_on` (`before insert or update of status`, function `public.books_set_finished_on()`, `security invoker`, `set search_path = ''`): when `new.status = 'finished'` and (insert, or `old.status <> 'finished'`) sets `new.finished_on = (now() at time zone 'utc')::date`; when `new.status <> 'finished'` sets `new.finished_on = null`; otherwise keeps it. This also covers a book created as Finished through the M1 form, without touching `insertBook`.
- Check `books_finished_on_matches_status`: `check ((status = 'finished') = (finished_on is not null))` (added after the backfill below, so rows created as Finished in M1 satisfy it).
- Rating and review are kept when a book leaves Finished (decision 0002); the app shows and edits them only while Finished, and the update functions refuse them otherwise.
- RLS policies added, `to authenticated`, on `(select auth.uid()) = user_id`:
  - `books_update_own` for `update` (`using` and `with check`), so a row can neither be reached nor handed to another user.
  - `books_delete_own` for `delete` (`using`).
- Column privileges: `revoke update on public.books from authenticated, anon; grant update (status, rating, review) on public.books to authenticated;`. Clients cannot write `user_id`, `finished_on`, `created_at` or `id`; the trigger still sets `finished_on` (privileges apply to the statement's columns, not to trigger changes). Title and author are not editable in M2.
- Indexes: none added. Filters (`status`) and stats (`finished_on` in a year) scan one user's rows through `books_user_id_created_at_idx`; a few hundred rows per user.

### Migrations
1. `<timestamp>_book_progress.sql` (F010): `add column finished_on date`, `add column rating smallint check (...)`, `add column review text check (...)`; backfill `update public.books set finished_on = (created_at at time zone 'utc')::date where status = 'finished'`; add `books_finished_on_matches_status`; the trigger function and trigger; `books_update_own`; the revoke/grant. `-- rollback: drop trigger books_set_finished_on on public.books; drop function public.books_set_finished_on(); drop policy books_update_own on public.books; grant update on public.books to authenticated, anon; alter table public.books drop constraint books_finished_on_matches_status, drop column review, drop column rating, drop column finished_on;`. Then `npm run db:types`, commit `lib/database.types.ts`.
2. `<timestamp>_books_delete_policy.sql` (F014): `create policy books_delete_own ...`. `-- rollback: drop policy books_delete_own on public.books;`. No type change.

F010 owns migration 1 because F011, F012 and F015 depend on it (through F010/F011). F014 depends only on F009, so it owns its own policy migration; the two can land in either order. F009, F013 and F016 add no migration. All are additive: no feature needs a `needs_human` migration decision.

## Contract
Types live in `lib/` on top of `lib/database.types.ts`. Server actions follow M1: `useActionState`, `(prev, formData)`, return the state. Actions on one book are bound to its id in the page (`updateStatus.bind(null, book.id)`), so their signature is `(id: string, prev, formData)`; every action re-checks `isUuid(id)` and `requireUser()`, because a bound argument is still client input.

`lib/books.ts` (pure parts and stub-client tests, as in M1):
- `type BookDetail = Book & Pick<Tables<"books">, "finished_on" | "rating" | "review">`.
- `isUuid(value: string): boolean` (8-4-4-4-12 hex).
- `getBook(supabase, id)`: F009 selects the M1 columns and returns `Promise<Book | null>`; F010 adds `finished_on, rating, review` to the select (after migration 1 and `db:types`) and changes the return type to `Promise<BookDetail | null>`. F014 and F016 may land before F010 and use only the M1 fields. `null` without a query when `!isUuid(id)`; `.eq("id", id).maybeSingle()`; RLS turns another user's id into `null`. Throws on other database errors.
- `listBooks(supabase, status?: BookStatus): Promise<Book[]>`: adds `.eq("status", status)` when given; order unchanged.
- `parseStatusFilter(value: string | string[] | undefined): BookStatus | undefined`: a known status, else `undefined` (All).
- `parseStatus(formData): Parsed<BookStatus, "status">`: unknown or missing → "Choose a status".
- `parseRating(formData): Parsed<number, "rating">`: integer 1 to 5, else "Choose a rating from 1 to 5".
- `parseReview(formData): Parsed<string, "review">`: trimmed, may be empty (saved as `null`), over 2,000 characters → "Review must be at most 2,000 characters".
- `updateBookStatus(supabase, id, status): Promise<boolean>`; `updateBookRating(supabase, id, rating)` and `updateBookReview(supabase, id, review | null)`: `Promise<boolean>`, filtered with `.eq("id", id).eq("status", "finished")`. Each uses `.select("id")` and returns `false` when no row changed (missing, someone else's, or not Finished). Throw on database errors.
- `removeBook(supabase, id): Promise<boolean>`: same pattern with `.delete()`.
- `formatFinishDate(date: string): string`: `"2026-11-02"` → `"November 2, 2026"` (`Intl.DateTimeFormat("en-US", { dateStyle: "long", timeZone: "UTC" })`). The page shows `Finished on November 2, 2026`.
- `type StatusFormState = FormState<"status">`, `RatingFormState = FormState<"rating">`, `ReviewFormState = FormState<"review">`; each adds `saved?: true` for a "Saved" confirmation.

`lib/stats.ts`:
- `type Stats = { finishedThisYear: number; averageRating: number | null }`.
- `summarizeStats(rows: { rating: number | null }[]): Stats`: count of rows; mean of non-null ratings rounded to one decimal, `null` when none.
- `getStats(supabase, now = new Date()): Promise<Stats>`: selects `rating` of own books with `finished_on >= <UTC year>-01-01` and `< <UTC year + 1>-01-01`, then `summarizeStats`.
- `formatAverage(value: number | null): string`: `null` → "No ratings yet", else `value.toFixed(1)` (`4.5` → "4.5", `4` → "4.0").

Server actions, `app/books/[id]/actions.ts`:
- `updateStatus(id, prev, formData): Promise<StatusFormState>`; `saveRating(id, prev, formData): Promise<RatingFormState>`; `saveReview(id, prev, formData): Promise<ReviewFormState>`. Parse errors → `{ fieldErrors, values }` (the stored value is untouched); `false` from the update → `formError: "Book not found"`; database error → `formError: "Could not save. Try again."`; success → `revalidatePath("/books")`, `revalidatePath(`/books/${id}`)`, return `{ saved: true }`.
- `deleteBook(id: string, _formData: FormData): Promise<void>` (bound with `.bind(null, id)` and used as the confirm form's `action`): `isUuid`, `requireUser()`, `removeBook`; then `revalidatePath("/books")` and `redirect("/books")` (also when nothing was deleted: the result for the user is the same). A database error is thrown to the route's error boundary, as `listBooks` does in M1.

Routes (added to M1's):
| route | access | does |
|---|---|---|
| `/books?status=` | signed in | `parseStatusFilter(searchParams.status)`; tab links All (`/books`), Want to read (`?status=want_to_read`), Reading (`?status=reading`), Finished (`?status=finished`), the current one with `aria-current="page"`; tabs always shown; one query (`listBooks(supabase, status)`). Rows → the list. No rows on the All tab → the M1 empty state (sentence + "Add book"). No rows on a filtered tab → "No books here". Titles link to `/books/<id>`. |
| `/books/[id]` | signed in | `requireUser()`, `getBook`; `null` → `notFound()`. Title as `h1` (serif), author, status badge, "Back to my books" link; Status form (shadcn `Select` + Save); when Finished: "Finished on …", rating form (shadcn `RadioGroup` with `name="rating"` and five `RadioGroupItem`s, values 1 to 5, accessible labels "1 star" … "5 stars", each shown with a `lucide-react` `Star` icon filled up to the selected value; the group is controlled, initialised from the saved rating; selection is exposed as `aria-checked`/`data-state="checked"` for the e2e test; "Rate" button submits (decision 0003)) and review form (shadcn `textarea`, label "Review", error next to it, "Post review" button (decision 0003)); Delete button opening an `AlertDialog` (Cancel / Delete) whose confirm submits `deleteBook`. |
| `/books/[id]` not found | signed in | `app/books/[id]/not-found.tsx`: heading "Book not found" and a link to `/books`; HTTP 404, see "Keeping the 404 status" below. |
| `/stats` | signed in | `requireUser()`, `getStats`; heading "Stats", "Books finished this year: <n>", "Average rating: <formatAverage>". |

Keeping the 404 status (Next 16 with `cacheComponents: true`): once a `<Suspense>` fallback or `loading.tsx` streams, the status is committed to 200 and a later `notFound()` only injects `noindex` (`node_modules/next/dist/docs/01-app/02-guides/streaming.md`, "Status codes"). So `app/books/[id]/page.tsx` sets `export const instant = false` (blocking render), awaits `params`, `requireUser()` and `getBook` and calls `notFound()` before rendering anything under a `<Suspense>`; there is no `loading.tsx` in `app/`, `app/books/` or `app/books/[id]/`; and the root layout reads the user for the header by awaiting `getUser()` directly (with `instant = false` on the layout if cacheComponents validation asks for it), not inside a `<Suspense>` boundary whose fallback could flush first. F016's e2e asserts `response.status() === 404` for the foreign id and for the nil UUID.

`proxy.ts`: the signed-out redirect also covers paths starting with `/stats`.
Header: when signed in, links "My books" (`/books`) and "Stats" (`/stats`) next to Sign out.

New shadcn components (`npx shadcn@4.21.3 add`): `select` (if F005 has not added it), `textarea`, `alert-dialog`, `radio-group`, `badge` as needed. `scripts/ui-tokens.py` rejects raw `<input>`/`<button>` outside `components/ui/`, so every control above is a shadcn component. Star icons come from `lucide-react` (already installed with shadcn).

## NFR
- Load: unchanged from M1 (tens of users, up to a few hundred books each). Every page is one or two queries per request, each limited to one user's rows; stats aggregate in memory over at most a few hundred rows. No new public page, so `lighthouserc.cjs` is unchanged; signed-in pages are covered by e2e with axe.
- Security: threats are reading, changing or deleting another user's book by guessing or replaying its id (pages and server actions are public endpoints), forging ownership or the finish date, and oversized input. RLS `using`/`with check` on update and delete limits every write to the caller's rows; column grants limit writes to `status`, `rating`, `review`; the trigger alone sets `finished_on`. Missing, malformed and foreign ids give the same `null` → 404 page, so the response does not reveal whether an id exists. Inputs are parsed in `lib/` and backed by the table checks (rating 1–5, review ≤ 2,000, status list). Reviews render as text (no `dangerouslySetInnerHTML`). Server actions keep Next's origin check.
- Cost: unchanged: local Docker, free-tier Supabase branch and Vercel preview.

## Decisions
- **Finish date set by a database trigger**, not by the app: it covers both a status update and a book created as Finished (M1's add form) with one rule, uses the database's UTC clock, and the client cannot forge it (no update grant on the column). Rejected: computing it in `updateBookStatus`, which would miss inserts and need a second code path in `insertBook`.
- **Column-level update grant** on `status`, `rating`, `review` in addition to the owner policy: RLS checks rows, not columns, and the anon key is public. Rejected: relying on the app sending only those fields.
- **Rating and review writes filtered on `status = 'finished'`** in the query rather than a table check, because decision 0002 keeps them when a book leaves Finished.
- **Three separate forms** (status, rating, review), matching decision 0002 ("saved independently") and the acceptance tests that save each on its own.
- **Tabs are links** with `aria-current`, rendered on the server from `?status=`, not a client tabs component: the URL is the state, reload and direct links work without client code.
- **Not found via `notFound()` and a route `not-found.tsx`**: one path for malformed, missing and foreign ids, served with 404.
- **`removeBook` returning `false` still redirects to `/books`**: deleting something already gone is not an error for the user.
- **Delete policy in its own migration (F014)** so F014 does not depend on F010.

Decision 0003 sets the rating form's button label and controlled value; no earlier decision changes.

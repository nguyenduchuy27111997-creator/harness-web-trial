# Design M3: edit title and author, search and sort the shelf in the URL, yearly reading goal on Stats

Builds on `docs/design/M1.md` and `docs/design/M2.md`: everything there (clients, `requireUser()`, form shapes, bound actions, blocking render on `/books` and `/books/[id]`, module rules) stays. Product choices are in `docs/decisions/0005-m3-replan.md`.

## Features
- F018 Edit title and author: migration 1 (update grant on `title`, `author`); `parseBookFields`, `updateBookFields`, `editBook` action; `edit-book-form` component on `/books/[id]`.
- F019 Edit validation: no new contract; field errors from `parseBookFields` shown next to each field, values kept. No migration.
- F020 Search: `parseSearch`, `filterBooks`, `booksHref`; `search-form` component; `StatusTabs` keeps `q` (and `sort`). No migration.
- F021 No matches: "No books match …" sentence and "Clear search" link built with `booksHref`. No migration.
- F022 Sort: `parseSort`, `sortBooks`, `SORT_LABELS`; `listBooks` also selects `rating`; `sort-select` component. No migration.
- F023 Set goal: migration 2 (`reading_goals` table); `lib/goals.ts` (`parseGoal`, `getReadingGoal`, `saveReadingGoal`, `goalProgress`); `saveGoal` action; `goal-form` component on `/stats`; shadcn `progress`.
- F024 Change goal: same contract as F023 (the upsert updates); "Change goal" button reopens the form prefilled. Uses migration 2.

## Data model
`public.books`: unchanged columns, checks, index and policies. Column privilege widened so the owner can fix a typo: `grant update (title, author) on public.books to authenticated;`. The M1 checks (title 1–200, author 1–120 characters) and `books_update_own` (`using` and `with check` on `user_id`) still guard every write.

New table `public.reading_goals`, one row per user per UTC calendar year:

| column | type | rules |
|---|---|---|
| `user_id` | `uuid` | `not null default auth.uid() references auth.users (id) on delete cascade` |
| `year` | `smallint` | `not null check (year between 2000 and 9999)` |
| `goal` | `smallint` | `not null check (goal between 1 and 365)` |
| `created_at` | `timestamptz` | `not null default now()` |

- Primary key `(user_id, year)`: one goal per user per year, and the index for the only lookup (own row for this year).
- RLS enabled. Policies `to authenticated` on `(select auth.uid()) = user_id`: `reading_goals_select_own` (select, `using`), `reading_goals_insert_own` (insert, `with check`), `reading_goals_update_own` (update, `using` and `with check`). No delete policy (not in scope).
- Privileges: `revoke all on public.reading_goals from anon, authenticated; grant select, insert (year, goal), update (year, goal) on public.reading_goals to authenticated;`. `user_id` comes only from the default and cannot be written; `update (year)` is needed because PostgREST's upsert writes `DO UPDATE SET year = excluded.year, goal = excluded.goal`.
- A new year has no row, so Stats invites the user to set a goal (decision 0005). Old rows are kept.

### Migrations
1. `<timestamp>_books_edit_grant.sql` (F018): `grant update (title, author) on public.books to authenticated;`. `-- rollback: revoke update (title, author) on public.books from authenticated;`. No type change (column privileges are not in `database.types.ts`).
2. `<timestamp>_reading_goals.sql` (F023): `create table public.reading_goals (...)`, `alter table ... enable row level security`, the three policies, the revoke/grant. `-- rollback: drop table public.reading_goals;`. Then `npm run db:types` and commit `lib/database.types.ts`.

Both are additive; no feature needs a `needs_human` migration decision. F018 and F023 do not depend on each other, so the two migrations can land in either order.

## Contract
Types live in `lib/` on top of `lib/database.types.ts`. Server actions follow M1/M2: `useActionState`, `(prev, formData)` (bound `(id, prev, formData)` for one book), return the state, re-check `requireUser()` and, for a book, `isUuid(id)`.

`lib/books.ts` (pure parts with unit tests, queries with stub-client tests as in M1/M2):
- `parseBookFields(formData): Parsed<{ title: string; author: string }, "title" | "author">`: trimmed; "Title is required", "Title must be at most 200 characters", "Author is required", "Author must be at most 120 characters". `parseNewBook` uses it for its title and author (same messages, its tests keep passing).
- `updateBookFields(supabase, id, { title, author }): Promise<boolean>`: `.update({ title, author }).eq("id", id).select("id")`; `false` when no row changed (missing or someone else's). Throws on database errors.
- `type EditBookFormState = FormState<"title" | "author"> & { saved?: true }`.
- `type BookSort = "newest" | "title" | "rating"`; `SORT_LABELS: Record<BookSort, string>` = "Newest added", "Title A to Z", "Highest rated".
- `parseSearch(value: string | string[] | undefined): string | undefined`: a string trimmed; empty → `undefined`.
- `parseSort(value: string | string[] | undefined): BookSort`: `"title"` or `"rating"`, else `"newest"`.
- `type ShelfBook = Book & Pick<Tables<"books">, "rating">`. `listBooks(supabase, status?)` keeps its signature, filter and order (newest first); F022 adds `rating` to its select and returns `Promise<ShelfBook[]>`.
- `filterBooks<T extends Book>(books: T[], q?: string): T[]`: no `q` → unchanged; else rows whose title or author contains `q`, both lower-cased (`toLocaleLowerCase("en")`).
- `sortBooks(books: ShelfBook[], sort: BookSort): ShelfBook[]`: returns a new array, stable over the input's newest-first order, so every tie stays newest first. `newest` → input order; `title` → `a.title.localeCompare(b.title, "en", { sensitivity: "base" })`; `rating` → effective rating descending, where the effective rating is `rating` only when `status === "finished"`, else unrated; unrated last.
- `booksHref({ status?, q?, sort? }): string`: `/books` plus the set parameters in the order `status`, `q`, `sort` (`URLSearchParams`, so `q` is encoded); `sort` omitted when `"newest"` or missing. Every link and navigation on `/books` is built with it.

`lib/goals.ts` (new):
- `GOAL_ERROR = "Goal must be a whole number from 1 to 365"`; `type GoalFormState = FormState<"goal"> & { saved?: true }`.
- `parseGoal(formData): Parsed<number, "goal">`: trimmed, `/^\d+$/` and 1 to 365, else `GOAL_ERROR` (rejects `0`, `366`, `2.5`, empty).
- `getReadingGoal(supabase, now = new Date()): Promise<number | null>`: own row for `now.getUTCFullYear()` (`.eq("year", year).maybeSingle()`), its `goal` or `null`. Throws on database errors.
- `saveReadingGoal(supabase, goal, now = new Date()): Promise<void>`: `.upsert({ year, goal }, { onConflict: "user_id,year" })` (user_id from the column default). Throws on database errors.
- `goalProgress(finished: number, goal: number): number`: `Math.min(100, Math.round((finished / goal) * 100))` (1 of 20 → 5, 1 of 10 → 10, 30 of 20 → 100).

Server actions:
- `app/books/[id]/actions.ts`: `editBook(id, prev, formData): Promise<EditBookFormState>`. Parse errors → `{ fieldErrors, values: { title, author } }` (raw input kept, nothing saved); `!isUuid(id)` or `false` → `formError: "Book not found"`; database error → `formError: "Could not save. Try again."`; success → `revalidatePath("/books")`, `revalidatePath(`/books/${id}`)`, `{ saved: true }`.
- `app/stats/actions.ts` (new): `saveGoal(prev, formData): Promise<GoalFormState>`. `requireUser()`; parse error → `{ fieldErrors, values: { goal } }`; database error → `formError: "Could not save. Try again."`; success → `revalidatePath("/stats")`, `{ saved: true }`. The year is the server's UTC year, never client input.

Routes (changed):
| route | access | does |
|---|---|---|
| `/books?status=&q=&sort=` | signed in | Parses all three (`parseStatusFilter`, `parseSearch`, `parseSort`); one query `listBooks(supabase, status)`, then `sortBooks(filterBooks(rows, q), sort)`. Above the list: `SearchForm` (label "Search", shadcn `Input` `name="q"` prefilled with `q`, "Search" button), `SortSelect` (label "Sort", shadcn `Select` showing `SORT_LABELS[sort]`), `StatusTabs` (hrefs keep `q` and `sort`). Empty states, first match wins: no rows and `q` → `No books match "<q>".` and a "Clear search" link to `booksHref({ status, sort })`; no rows and `status` → "No books here" (M2); no rows → the M1 empty shelf. "Add book" shows as in M2, also when `q` is set. Stays `instant = false`. |
| `/books/[id]` | signed in | As M2, plus an "Edit" button (F018) that shows `EditBookForm` in place: Title and Author (`FormField` with shadcn `Input`, prefilled, errors next to each field, no `maxLength`/`required` attributes so the server messages show), Save and Cancel. Cancel closes without saving; `saved` closes it and the revalidated page shows the new heading. |
| `/stats` | signed in | As M2, plus `getReadingGoal` (both queries in one `Promise.all`). No goal → a sentence inviting the user to set a goal for this year and `GoalForm` (label "Reading goal", shadcn `Input` `inputMode="numeric"`, no `min`/`max`/`step` attributes, "Set goal"). A goal → "<n> of <goal> books finished this year", shadcn `Progress` with `value={goalProgress(n, goal)}` and accessible name "Reading goal progress", and a "Change goal" button that opens `GoalForm` prefilled with the goal ("Save goal"). Errors show next to the field. |

Client components and the URL: `SearchForm` and `SortSelect` are client components that call `router.push(booksHref(...))` with the current `status` and the other parameter, so an empty search drops `q` and the URL is always canonical. `SearchForm` is keyed by `q` so the field follows the URL (for example after "Clear search"). Tabs and "Clear search" are server-rendered links (M2).

New shadcn component: `progress` (`npx shadcn@4.21.3 add progress`).

## NFR
- Load: unchanged (tens of users, up to a few hundred books each). `/books` stays one query over one user's rows; search and sort run in memory on those rows, at most a few hundred, in well under a millisecond. `/stats` adds one primary-key lookup. No new public page, so `lighthouserc.cjs` is unchanged; signed-in pages are covered by e2e with axe.
- Security: threats are changing another user's book title or goal, forging `user_id`, oversized input, and injecting into a query through `q`. Book edits go through `books_update_own` and the title/author checks; goals through the three owner policies, the column grants (no `user_id`) and the 1–365 check. `q` never reaches the database (filtered in memory), so it cannot change a PostgREST filter or a `like` pattern; it renders as text. Unknown `sort`/`status` values fall back to defaults. The goal's year is set on the server.
- Cost: unchanged: local Docker, free-tier Supabase branch and Vercel preview.

## Decisions
- **Search and sort in memory** after the one existing query, not in SQL: a few hundred rows per user, no user input in a PostgREST `or=` filter or `ilike` pattern (no escaping of `,`, `()`, `%`, `_`), and pure functions with unit tests. Rejected: `.or("title.ilike.*q*,author.ilike.*q*")` and `order()` with a nullable computed rating; revisit with an index if shelves grow to thousands.
- **`listBooks` keeps its signature** and only gains `rating` in its select, so M2 callers and tests stay valid.
- **Effective rating counts only Finished books** for "Highest rated" (decision 0005); computed in `sortBooks`, no column.
- **`booksHref` as the one URL builder** for tabs, search, sort and "Clear search", so every control keeps the other parameters the same way.
- **Search and sort navigate with `router.push`** rather than a plain GET form, so an empty search leaves no `q=` in the URL and the sort applies on selection.
- **Goal keyed by `(user_id, year)` with an upsert**: setting and changing are one action; a new year simply has no row. Rejected: one goal column per user (would carry last year's goal into the new year, against decision 0005).
- **Column grants on `reading_goals`** mirror M2's on `books`: RLS checks rows, not columns, and the anon key is public.
- **Edit grant in its own migration (F018)**: M2's column grant deliberately left title and author read-only; widening it is additive and is the only schema change editing needs.

No earlier design or decision changes; M3's product choices are in decision 0005.

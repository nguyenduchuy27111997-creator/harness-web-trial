# Design M6: reading history (start dates, editable dates, reading again with past reads, monthly/pages stats, year in review)

Builds on `docs/design/M1.md` to `M5.md`: everything there (clients, `requireUser()`, form shapes, bound actions, blocking render, `ConfirmDeleteButton` from decision 0008, the `finished_on` trigger, composite foreign keys, module rules) stays. Product choices are in `docs/decisions/0013-m6-replan.md`.

## Features
- F052 Start date on Reading: migration 1 (`books.started_on`, its trigger, checks, grants); `BookDetail` gains `started_on`; "Started on <date>" on `/books/[id]`.
- F053 Dates and days read: `formatReadDays`; `reading-dates` component on `/books/[id]`. Uses migration 1.
- F054 Edit dates: `parseReadingDates` (shape only), `updateReadingDates`, `editDates` action; `edit-dates-form` in place. Uses migration 1 (grants).
- F055 Date validation: the rules in `parseReadingDates`; messages next to Finished. Uses migration 1 (checks as a backstop).
- F056 Read again: migration 2 (`reads`, `read_again()`); `lib/reads.ts` (`readAgain`, `listPastReads`); `readBookAgain` action; `read-again-button`, `past-reads` on `/books/[id]`.
- F057 Delete a past read: `removePastRead`, `deletePastRead` action; `ConfirmDeleteButton`. Uses migration 2.
- F058 Stats count reads: `listFinishedReads`; `getStats` counts every finished read; average stays on current ratings. No migration.
- F059 Finished by month: `countByMonth`, `getFinishedByMonth`; `monthly-chart` on `/stats`. No migration (decision 0014).
- F060 Pages read: `sumPages`, `formatPagesRead`; line on `/stats`. No migration.
- F061 Year in review: `parseYear`; route `/stats/[year]` with its `not-found.tsx` (HTTP 404); `app/stats/page.tsx` and `app/stats/loading.tsx` move into the route group `app/stats/(overview)/`; "Year in review" link on `/stats`; `year-review` component. No migration.
- F062 Year average, highest rated, year links: `summarizeYear`; additions to `year-review`. No migration.
- F063 Isolation: the RLS, grants and foreign key of migration 2; an e2e spec using B's session through `@supabase/supabase-js` against the local stack (like F051): B's select and delete of A's read by id return `[]` with no error, B's update returns error code `42501` (no update grant), B's `rpc("read_again")` on A's book returns `false`, and A's two reads are unchanged afterwards. No app change.

## Data model
Every M1–M5 table stays. Dates are UTC calendar dates (`(now() at time zone 'utc')::date`), like `finished_on`; "today" in the app is `new Date().toISOString().slice(0, 10)`.

`public.books` gains:

| column | type | rules |
|---|---|---|
| `started_on` | `date` | null |

- `constraint books_started_on_status check (status <> 'want_to_read' or started_on is null)`.
- `constraint books_started_before_finished check (started_on is null or finished_on is null or started_on <= finished_on)`.
- Existing rows get `started_on = null` (decision 0013: no backfill), which passes both checks.
- Trigger `books_set_started_on`, `before insert or update of status`, `security invoker`, `set search_path = ''`, mirroring `books_set_finished_on`:
  - `new.status = 'reading'` and (`INSERT` or `old.status <> 'reading'`) → `started_on = today`;
  - `new.status = 'want_to_read'` → `started_on = null`;
  - `new.status = 'finished'`: on `INSERT` → `null` (a book added as Finished has no start date); on update, kept (Reading → Finished keeps it; Want to read → Finished stays null).
- `grant update (started_on, finished_on) on public.books to authenticated;` for editing dates. Changing `finished_on` alone does not fire `books_set_finished_on` (`update of status`), and `books_finished_on_matches_status` stops setting it on a book that is not finished or clearing it on one that is. Future dates are checked by the app only (a check constraint cannot use `now()`).

New table `public.reads` (past reads; the current read stays on `books`):

| column | type | rules |
|---|---|---|
| `id` | `uuid` | `primary key default gen_random_uuid()` |
| `book_id` | `uuid` | `not null` |
| `user_id` | `uuid` | `not null default auth.uid()` |
| `started_on` | `date` | null |
| `finished_on` | `date` | `not null` |
| `rating` | `smallint` | null, `check (rating between 1 and 5)` |
| `created_at` | `timestamptz` | `not null default now()` |

- `check (started_on is null or started_on <= finished_on)`.
- `foreign key (book_id, user_id) references public.books (id, user_id) on delete cascade` (as notes and quotes): same owner always; deleting the book or the user deletes its reads.
- `create index reads_book_id_finished_on_idx on public.reads (book_id, finished_on desc);` for a book's past reads; `create index reads_user_id_finished_on_idx on public.reads (user_id, finished_on);` for year ranges.
- RLS enabled. Policies `to authenticated` on `(select auth.uid()) = user_id`: `reads_select_own`, `reads_insert_own` (`with check`), `reads_delete_own`. No update policy.
- `revoke all on public.reads from anon, authenticated; grant select, insert (book_id, started_on, finished_on, rating), delete on public.reads to authenticated;`. No update grant: a past read is never edited, so any update (mine or someone else's) is refused.

Function `public.read_again(p_book_id uuid) returns boolean`, `language plpgsql`, `security invoker`, `set search_path = ''` (RLS of the caller applies to every statement):
1. `select started_on, finished_on, rating from public.books where id = p_book_id and status = 'finished' for update` into a record; not found → `return false` (missing, someone else's, or not finished; the lock makes a double click insert one read).
2. `insert into public.reads (book_id, started_on, finished_on, rating)` with those values.
3. `update public.books set status = 'reading', rating = null, current_page = case when total_pages is null then null else 0 end where id = p_book_id;` — the triggers set `started_on` to today and `finished_on` to null; the review is kept.
4. `return true`.
- `revoke execute on function public.read_again(uuid) from public, anon; grant execute on function public.read_again(uuid) to authenticated;`.

### Migrations
Each ends with `npm run db:types` and a commit of `lib/database.types.ts`. Timestamps later than every migration on `main` when each lands.
1. `<timestamp>_books_started_on.sql` (F052): `add column started_on date`, the two checks, `books_set_started_on()` function and trigger, the update grant. `-- rollback: drop trigger books_set_started_on on public.books; drop function public.books_set_started_on(); revoke update (started_on, finished_on) on public.books from authenticated; alter table public.books drop constraint books_started_before_finished, drop constraint books_started_on_status, drop column started_on;`
2. `<timestamp>_reads.sql` (F056): `create table public.reads (...)`, its indexes, enable RLS, three policies, revoke/grant, `read_again` and its execute grants. `-- rollback: drop function public.read_again(uuid); drop table public.reads;`

Both only add: no feature needs a `needs_human` migration decision.

## Contract
Types live in `lib/` on top of `lib/database.types.ts`. Actions follow M1–M5: bound ids, `requireUser()` and `isUuid` on every bound id, queries throw, actions turn a throw into `formError: "Could not save. Try again."`; foreign, missing and malformed ids all read as "missing". A `Read` is one finished reading of a book: the book's current read (when finished) or a row of `reads`.

`lib/books.ts` (changed):
- `BookDetail` adds `started_on`; `getBook` selects it.
- `formatReadDays(startedOn: string, finishedOn: string): string`: whole days between the dates plus one; `"Read in 1 day"`, `"Read in 12 days"` (2026-10-01 → 2026-10-12).
- `type DatesFormState = FormState<"started_on" | "finished_on"> & { saved?: true }`.
- `parseReadingDates(formData, status: BookStatus, today: string): Parsed<{ started_on: string | null; finished_on?: string }, "started_on" | "finished_on">`: fields `started_on` and (only when `status === "finished"`) `finished_on`, trimmed, from `<input type="date">` (`YYYY-MM-DD`). Started: empty → `null`; not a valid date → "Enter a valid date". Finished: empty → "Finish date is required"; invalid → "Enter a valid date". F055 adds: a date after `today` → "The date cannot be in the future" (on that field); started after finished → on Finished, "The finish date cannot be before the start date". All checks run, so both fields can show an error. `today` is a parameter so tests are deterministic.
- `updateReadingDates(supabase, id, status, dates): Promise<boolean>`: `.update(dates).eq("id", id).eq("status", status).select("id")`; `false` when no row (missing, someone else's, or the status changed meanwhile). A Want to read book has no dates to edit.

`lib/reads.ts` (new; queries with stub-client tests):
- `type PastRead = Pick<Tables<"reads">, "id" | "started_on" | "finished_on" | "rating">`.
- `readAgain(supabase, bookId): Promise<boolean>`: `supabase.rpc("read_again", { p_book_id: bookId })`; the returned boolean.
- `listPastReads(supabase, bookId): Promise<PastRead[]>`: `book_id = bookId`, ordered `finished_on` desc, `created_at` desc, `id` desc.
- `removePastRead(supabase, bookId, id): Promise<boolean>`: `.delete().eq("id", id).eq("book_id", bookId).select("id")`.

`lib/stats.ts` (changed; pure parts with unit tests, queries with stub-client tests):
- `type FinishedRead = { bookId: string; title: string; finishedOn: string; rating: number | null; totalPages: number | null; pastReadId: string | null }` (`pastReadId` null for a book's current read).
- `listFinishedReads(supabase, year: number): Promise<FinishedRead[]>`: two queries in `Promise.all`, both `finished_on >= <year>-01-01 and < <year+1>-01-01`: `books.select("id, title, finished_on, rating, total_pages")` and `reads.select("id, finished_on, rating, book:books(id, title, total_pages)")`; merged and sorted `finishedOn` desc, then current reads before past reads, then `bookId`, then `pastReadId`.
- `summarizeStats` unchanged. `Stats` grows with `pagesRead: number` (F060); F059's monthly counts are not on `Stats` (decision 0014). `getStats(supabase, now)` calls `listFinishedReads(supabase, now.getUTCFullYear())`: `finishedThisYear = reads.length`; `averageRating = summarizeStats(reads.filter(r => r.pastReadId === null)).averageRating` (books' current ratings only, decision 0013).
- `countByMonth(reads): number[]`: 12 counts, index 0 = January, by `finishedOn` month.
- `getFinishedByMonth(supabase, now = new Date()): Promise<number[]>`: `countByMonth(await listFinishedReads(supabase, now.getUTCFullYear()))`; `/stats` runs it in its `Promise.all` beside `getStats`.
- `sumPages(reads): number`: sum of `totalPages`, a null adds 0. `formatPagesRead(n)`: `"370 pages read this year"`, `"1 page read this year"`, `"0 pages read this year"` (`toLocaleString("en-US")`).
- `parseYear(value: string, now = new Date()): number | null`: `/^\d{4}$/` and `1000 <= year <= now.getUTCFullYear()`, else `null`.
- `summarizeYear(reads): { count: number; averageRating: number | null; highestRated: FinishedRead[] }`: average of the rated reads to one decimal (as `summarizeStats`), `null` when none rated; `highestRated` = the rated reads whose rating equals the top rating, in list order; empty when none rated.
- Goal progress on `/stats` uses `finishedThisYear`, so it counts reads too.

Server actions in `app/books/[id]/actions.ts` (added). All revalidate `/books/${bookId}`, `/books` and `/stats` (and so `/stats/[year]`, rendered on request):
- `updateStatus` (changed, F052): also revalidates `/stats`.
- `editDates(bookId, prev, formData): Promise<DatesFormState>`: `!isUuid` → `formError: "Book not found"`; `getBook` (null or `want_to_read` → "Book not found"); `parseReadingDates(formData, book.status, today)`; parse error → `{ fieldErrors, values }`, nothing saved; `updateReadingDates` `false` → "Book not found"; a `23514` check violation (a race against the rules) → `fieldErrors.finished_on: "The finish date cannot be before the start date"`; success → `{ saved: true }` (the form closes).
- `readBookAgain(bookId, formData): Promise<void>`: calls `readAgain` from `lib/reads.ts` when `isUuid`; a `false` changes nothing.
- `deletePastRead(bookId, readId, formData): Promise<void>`: `removePastRead` when both are UUIDs.

## Modules
Same folders and import rules as M1–M5, enforced unchanged by `.dependency-cruiser.cjs`:
- `lib/` must not import `app/` or `components/`.
- `components/` must not import `app/`, `lib/supabase/` or `@supabase/*`.
- `@supabase/ssr` is imported only by `lib/supabase/`.
- No cycles (`no-circular`).

New in M6: `lib/reads.ts`, `app/stats/[year]/page.tsx` (no actions). New components: `reading-dates`, `edit-dates-form`, `read-again-button`, `past-reads`, `monthly-chart`, `year-review`; they receive data and bound actions as props and may import types and pure helpers from `lib/books.ts`, `lib/reads.ts` and `lib/stats.ts`. The F063 e2e spec may import `@supabase/supabase-js`; `e2e/` is outside the depcruise scope.

## NFR
- Load: unchanged (tens of users, a few hundred books each); expect a handful of past reads per book. `/books/[id]` adds one indexed query in its `Promise.all`; `/stats` runs `listFinishedReads` twice (`getStats` and `getFinishedByMonth`, decision 0014: four indexed range queries) and `/stats/[year]` once (two), each of at most a few hundred rows (PostgREST `max_rows` 1,000 bounds them); counting is in memory. Read again is one round trip (`rpc`), one transaction. No new public page.
- Security: threats are reading, deleting or forging another user's reads, attaching a read to their book, reading again someone else's book, editing their dates, and probing ids through bound arguments or `/stats/<year>`. Owner RLS on `reads` and `books`; no update grant on `reads`; column grants keep `user_id`, `created_at` and `id` out of reach; the composite foreign key makes a cross-owner read impossible; `read_again` is `security invoker`, so its select, insert and update run under the caller's RLS and return `false` for a foreign book; `anon` cannot execute it. The year never reaches a query unparsed. Foreign ids give "not found".
- Cost: unchanged: local Docker, free-tier Supabase branch and Vercel preview.

## Decisions
- **Past reads in a `reads` table, current read stays on `books`**: M1–M5 code (status, rating, review, finished_on trigger, filters, sorting) keeps working untouched. Rejected: moving every read into `reads` with the book pointing at the current one (rewrites every query and the M2 trigger).
- **`started_on` set by a trigger on status**, like `finished_on`: one rule wherever the status changes. Rejected: setting it in `updateBookStatus` (two writers of the same rule).
- **Read again as a `security invoker` Postgres function**: insert-then-update in one transaction with a row lock, so a failure or a double click never leaves a duplicate or lost read. Rejected: two PostgREST calls from the action (not atomic); `security definer` (would bypass RLS and need its own owner checks).
- **Future-date and order rules in the app** (`parseReadingDates`), order and status also as checks in the database. Rejected: a trigger for "not in the future" (`now()` cannot be in a check; app validation with a UTC `today` matches how `finished_on` is set).
- **Counting from one `listFinishedReads`** for `/stats` and `/stats/[year]`, in memory: one place for decision 0013's counting rule. Rejected: SQL aggregates or a view (another schema object to keep under RLS for a few hundred rows).
- **No update on `reads`**: nothing edits a past read; deleting is the only change.
- **Monthly counts beside `Stats`** (decision 0014): `getFinishedByMonth` next to `getStats`, so F058's `getStats` assertions stay as they are. Rejected: `byMonth` on `Stats` (changes those assertions).
- **Year range 1000 to this year**, so a 4-digit year is valid and "Previous year" stops at 1000.

No earlier design or decision changes.

# Design M5: notes and quotes on a book's page, a searchable /quotes page, cascade on book delete

Builds on `docs/design/M1.md` to `M4.md`: everything there (clients, `requireUser()`, form shapes, bound actions, in-memory search, blocking render, `ConfirmDeleteButton` from decision 0008, module rules) stays. Product choices are in `docs/decisions/0009-m5-replan.md`.

## Features
- F040 Notes: migration 1 (`notes`); `lib/notes.ts` (`parseNote`, `listNotes`, `insertNote`, `formatNoteDate`); `addNote` action; `book-notes` section on `/books/[id]`.
- F041 Note validation: `parseNote` messages next to the field. Uses migration 1.
- F042 Edit a note: `updateNote`, `editNote` action; `edit-note-form` in place. Uses migration 1.
- F043 Delete a note: `removeNote`, `deleteNote` action; `ConfirmDeleteButton`. Uses migration 1.

- F045 Quote validation: `parseQuote` messages, page bound from the book's `total_pages`. Uses migration 2.
- F046 Edit a quote: `updateQuote`, `editQuote` action; `edit-quote-form` in place. Uses migration 2.

## Data model
`public.books` and every M1–M4 table stay unchanged. Both new tables reference `books_id_user_id_key unique (id, user_id)` (from M4 migration 2).

New table `public.notes`:

| column | type | rules |
|---|---|---|
| `id` | `uuid` | `primary key default gen_random_uuid()` |
| `book_id` | `uuid` | `not null` |
| `user_id` | `uuid` | `not null default auth.uid()` |
| `body` | `text` | `not null check (char_length(body) between 1 and 2000)` |
| `created_at` | `timestamptz` | `not null default now()` |

- `foreign key (book_id, user_id) references public.books (id, user_id) on delete cascade`: a note belongs to a book of its own owner (checked on every row, whatever RLS hides); deleting the book (or, through `books.user_id`, the user) deletes its notes. No direct `user_id` foreign key, like `book_shelves`, so `books` is the only relationship PostgREST sees.
- `create index notes_book_id_created_at_idx on public.notes (book_id, created_at desc);` for one book's notes, newest first.
- RLS enabled. Policies `to authenticated` on `(select auth.uid()) = user_id`: `notes_select_own` (select), `notes_insert_own` (insert, `with check`), `notes_update_own` (update, `using` and `with check`), `notes_delete_own` (delete).
- `revoke all on public.notes from anon, authenticated; grant select, insert (book_id, body), update (body), delete on public.notes to authenticated;`: `user_id`, `created_at` and `id` come from defaults and never change, so editing keeps the date and a note cannot move to another book.

New table `public.quotes`:

| column | type | rules |
|---|---|---|
| `id` | `uuid` | `primary key default gen_random_uuid()` |
| `book_id` | `uuid` | `not null` |
| `user_id` | `uuid` | `not null default auth.uid()` |
| `body` | `text` | `not null check (char_length(body) between 1 and 1000)` |
| `page` | `smallint` | null, `check (page between 1 and 10000)` |
| `created_at` | `timestamptz` | `not null default now()` |

- Same composite foreign key with `on delete cascade`, same reason.
- `create index quotes_book_id_created_at_idx on public.quotes (book_id, created_at desc);` for a book's quotes; `create index quotes_user_id_created_at_idx on public.quotes (user_id, created_at desc);` for `/quotes`.
- RLS enabled. Policies `quotes_select_own`, `quotes_insert_own`, `quotes_update_own`, `quotes_delete_own`, as for notes.
- `revoke all on public.quotes from anon, authenticated; grant select, insert (book_id, body, page), update (body, page), delete on public.quotes to authenticated;`.
- The bound "page at most the book's total pages" is checked by the app when a quote is saved, not by the database (decision 0009: changing the total later leaves quotes as they are, which a constraint or trigger would contradict). The database holds the 1 to 10,000 range.

The app trims text; the database stores what it is given within the length checks.

### Migrations
Each ends with `npm run db:types` and a commit of `lib/database.types.ts`.
1. `<timestamp>_notes.sql` (F040): `create table public.notes (...)`, its index, enable RLS, four policies, revoke/grant. `-- rollback: drop table public.notes;`
2. `<timestamp>_quotes.sql` (F044): `create table public.quotes (...)`, its two indexes, enable RLS, four policies, revoke/grant. `-- rollback: drop table public.quotes;`

Both only add tables: no feature needs a `needs_human` migration decision. The note and quote chains are independent (both depend only on F009); timestamps must be later than every migration on `main` when each lands.

## Contract
Types live in `lib/` on top of `lib/database.types.ts`. Server actions follow M1–M4: `useActionState` with bound `(…ids, prev, formData)`, or a plain `(…ids, formData) => Promise<void>` form action for delete buttons; each re-checks `requireUser()` and `isUuid` on every bound id. Database errors: queries throw; actions turn that into `formError: "Could not save. Try again."`. Every query is filtered by RLS; foreign, missing and malformed ids all read as "missing".

`lib/notes.ts` (new; pure parts with unit tests, queries with stub-client tests):
- `type Note = Pick<Tables<"notes">, "id" | "body" | "created_at">`.
- `type NoteFormState = FormState<"note"> & { saved?: true }`.
- `parseNote(formData): Parsed<string, "note">`: field `note`, trimmed; empty → "Note is required"; over 2,000 characters → "Note must be at most 2,000 characters".
- `listNotes(supabase, bookId): Promise<Note[]>`: `book_id = bookId`, ordered `created_at` desc, then `id` desc.
- `insertNote(supabase, bookId, body): Promise<"ok" | "missing">`: insert `{ book_id, body }`; `23503` (not the user's book, or gone) or `42501` → `"missing"`.
- `updateNote(supabase, bookId, id, body): Promise<boolean>`: `.update({ body }).eq("id", id).eq("book_id", bookId).select("id")`; `false` when no row (missing, someone else's, or not on that book).
- `removeNote(supabase, bookId, id): Promise<boolean>`: `.delete().eq("id", id).eq("book_id", bookId).select("id")`.
- `formatNoteDate(createdAt: string): string`: the UTC date of the timestamp in the `formatFinishDate` style (`"2026-11-06T10:00:00+00:00"` → `"November 6, 2026"`), UTC like `finished_on`.

`lib/quotes.ts` (new; same test split):
- `type BookQuote = Pick<Tables<"quotes">, "id" | "body" | "page" | "created_at">`.
- `type Quote = BookQuote & { book: Pick<Tables<"books">, "id" | "title"> }`.
- `type QuoteFormState = FormState<"quote" | "page"> & { saved?: true }`.
- `parseQuote(formData, totalPages: number | null): Parsed<{ body: string; page: number | null }, "quote" | "page">`: field `quote`, trimmed; empty → "Quote is required"; over 1,000 → "Quote must be at most 1,000 characters". Field `page`, trimmed; empty → `null`; else must match `/^\d+$/` and be 1 to `max = totalPages ?? 10000`, else "Page must be a whole number from 1 to <max>" (`10,000` and `250` formatted with `toLocaleString("en-US")`). Both fields are checked, so both errors can show.
- `listBookQuotes(supabase, bookId): Promise<BookQuote[]>`: ordered `created_at` desc, then `id` desc.
- `listQuotes(supabase): Promise<Quote[]>`: all own quotes, `select("id, body, page, created_at, book:books(id, title)")`, same order.
- `insertQuote(supabase, bookId, { body, page }): Promise<"ok" | "missing">`: as `insertNote`.
- `updateQuote(supabase, bookId, id, { body, page }): Promise<boolean>`: filtered on `id` and `book_id`, like `updateNote`, so the bound book, the page limit and the changed row always agree; a mismatch is `false`.
- `removeQuote(supabase, bookId, id): Promise<boolean>`: as `removeNote`.
- `filterQuotes(quotes: Quote[], q?: string): Quote[]`: no `q` → unchanged; else quotes whose `body` or `book.title` contains `q`, compared with `toLocaleLowerCase("en")` like `filterBooks`; order kept.
- `quotesHref(q?: string): string`: `/quotes` or `/quotes?q=<encoded>`.
- `/quotes` reads `q` with `parseSearch` from `lib/books.ts` (trimmed, empty → none).

Server actions in `app/books/[id]/actions.ts` (added). All revalidate `/books/${bookId}`; quote actions also `/quotes`:
- `addNote(bookId, prev, formData): Promise<NoteFormState>`: parse error → `{ fieldErrors, values: { note } }`; `!isUuid(bookId)` or `"missing"` → `formError: "Book not found"`; success → `{ saved: true }` (the form clears).
- `editNote(bookId, noteId, prev, formData): Promise<NoteFormState>`: parse error → `fieldErrors` with the value kept, nothing saved; `!isUuid` or `false` → `formError: "Note not found"`; success → `{ saved: true }` (the form closes).
- `deleteNote(bookId, noteId, formData): Promise<void>`: `removeNote` when both are UUIDs.
- `addQuote(bookId, prev, formData): Promise<QuoteFormState>`: `!isUuid(bookId)` → "Book not found"; `getBook` for `total_pages` (`null` book → `formError: "Book not found"`); `parseQuote(formData, book.total_pages)`; parse error → `{ fieldErrors, values: { quote, page } }`; then `insertQuote` (`"missing"` → "Book not found"); success → `{ saved: true }`.
- `editQuote(bookId, quoteId, prev, formData): Promise<QuoteFormState>`: as `addQuote` (same bound from the book), then `updateQuote`; `false` → "Quote not found".
- `deleteQuote(bookId, quoteId, formData): Promise<void>`.
- `deleteBook` (changed, F050): also `revalidatePath("/quotes")`.

## Modules
Same folders and import rules as M1–M4, enforced unchanged by `.dependency-cruiser.cjs`:
- `lib/` must not import `app/` or `components/`.
- `components/` must not import `app/`, `lib/supabase/` or `@supabase/*`.
- `@supabase/ssr` is imported only by `lib/supabase/`.
- No cycles. `lib/notes.ts` and `lib/quotes.ts` may import `lib/books.ts` (`isUuid`, `parseSearch`) and `lib/forms.ts`; `lib/books.ts` and `lib/shelves.ts` must not import them, and they do not import each other.

New in M5: `lib/notes.ts`, `lib/quotes.ts`, `app/quotes/page.tsx` (no actions file; quote changes happen on the book page). New components: `book-notes`, `note-form`, `edit-note-form`, `book-quotes`, `quote-form`, `edit-quote-form`, `quote-search-form`; they receive data and bound actions as props and may import types from `lib/notes.ts` and `lib/quotes.ts`; `quote-search-form` may import `next/navigation` and `quotesHref`/`parseSearch`. Add shadcn `textarea` if it is not in `components/ui/`. The e2e isolation spec (F051) may import `@supabase/supabase-js`; `e2e/` is outside the depcruise scope.

## NFR
- Load: unchanged (tens of users, a few hundred books each); expect tens of notes and quotes per book and at most a few hundred quotes per user. PostgREST caps a response at 1,000 rows (`max_rows` in `supabase/config.toml`), which bounds `/quotes` and its in-memory search; paging is out of scope until a user nears that. `/books/[id]` adds two indexed queries in the same `Promise.all`. `/quotes` is one indexed query with an embedded book title, filtered in memory like `/books`. No pagination in scope. No new public page.
- Security: threats are reading or changing another user's notes or quotes, attaching mine to their book (or theirs to mine), forging `user_id` or `created_at`, moving a note to another book, and probing ids through bound arguments or `?q=`. Owner RLS on both tables; column grants leave `user_id`, `created_at` and `book_id` (after insert) out of reach; the composite foreign keys make a cross-owner row impossible even if a policy were wrong; foreign ids give "not found", never a different error. `q` never reaches a query. Text is rendered by React (escaped), never as HTML.
- Cost: unchanged: local Docker, free-tier Supabase branch and Vercel preview.

## Decisions
- **Two tables, `notes` and `quotes`**, not one table with a kind: different lengths, quotes have a page and a cross-book page, notes do not. Rejected: one `book_entries` table (nullable `page` only for one kind, a check per kind, every query filters on kind).
- **Composite foreign key `(book_id, user_id)` with cascade**, as `book_shelves` in M4: same-owner guarantee in the schema, and "deleting a book deletes its notes and quotes" holds without app code. Rejected: an `exists` check in the insert policy (rests on RLS of two tables).
- **Page bound in the app** (`parseQuote` with the book's `total_pages`, read in the action), range 1 to 10,000 in the database. Rejected: a trigger comparing with `books.total_pages` (it would also need to fire when the total changes, which decision 0009 says must not touch quotes; the read-then-insert race only matters if the same user changes the total in another tab at the same moment).
- **Quote search in memory** over `listQuotes`, like M3's book search: `q` never reaches a query and matching the joined book title needs no PostgREST `or` across an embed. Rejected: `ilike` filters (escaping, embedded-column `or`).
- **No `updated_at`**: the shown date is the writing date (decision 0009), and nothing reads an edit time.
- **Column `body`** for both texts, since `text` is a type name; the form fields are named `note`, `quote` and `page` so the field errors match the labels.

No earlier design or decision changes.

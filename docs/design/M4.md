# Design M4: named shelves, books on shelves, a shelf filter on /books, and reading progress

Builds on `docs/design/M1.md`, `M2.md` and `M3.md`: everything there (clients, `requireUser()`, form shapes, bound actions, `booksHref`, in-memory search and sort, blocking render on `/books` and `/books/[id]`, module rules) stays. Product choices are in `docs/decisions/0007-m4-replan.md`.

## Features
- F028 Shelves page: migration 1 (`shelves`); `lib/shelves.ts` (`parseShelfName`, `listShelves`, `insertShelf`); `createShelf` action; route `/shelves`; "Shelves" header link.
- F029 Name validation: `parseShelfName` messages and the unique index's duplicate error, shown next to the field. Uses migration 1.
- F030 Rename: `renameShelf` action, `updateShelfName`; `rename-shelf-form` in place on `/shelves`. Uses migration 1.
- F031 Put a book on shelves: migration 2 (`book_shelves`); `listBookShelfIds`, `parseShelfChoice`, `addBookToShelf`; `addToShelf` action; `book-shelves` section on `/books/[id]`.
- F032 Take a book off: `removeBookFromShelf`, `removeFromShelf` action; "Remove from <name>" buttons in `book-shelves`. Uses migration 2.
- F033 Delete a shelf: `removeShelf`, `deleteShelf` action; `delete-shelf-button` (shadcn `alert-dialog`). Links go by cascade; books stay. Uses migrations 1 and 2.
- F034 Shelf filter: `parseShelfFilter`, `listShelfBookIds`, `filterByShelf`; `booksHref` gains `shelf`; `shelf-select` on `/books`; every `/books` control keeps `shelf`. No migration.
- F035 Progress: migration 3 (`total_pages`, `current_page` on `books`); `parseProgress`, `updateBookProgress`, `progressPercent`, `formatProgress`; `saveProgress` action; `progress-form` on `/books/[id]` while Reading; `getBook` selects the two columns.
- F036 Progress validation: `parseProgress` messages next to each field. Uses migration 3.
- F037 Progress in the list: `listBooks` also selects the two columns; `BookList` shows "N%" and shadcn `Progress` for Reading books with progress. Uses migration 3.
- F038 Finishing sets the page to the total: migration 4 (trigger `books_finish_progress`). No app change.

## Data model
`public.books`: all M1–M3 columns, checks, triggers, policies and grants stay. Added (migration 2) `constraint books_id_user_id_key unique (id, user_id)`, the target of `book_shelves`' composite foreign key. Added (migration 3):

| column | type | rules |
|---|---|---|
| `total_pages` | `smallint` | null, `check (total_pages between 1 and 10000)` |
| `current_page` | `smallint` | null, `check (current_page >= 0)` |

- Check `books_progress_pair`: `check ((total_pages is null) = (current_page is null) and (current_page is null or current_page <= total_pages))`. Existing rows have neither, so they pass.
- `grant update (total_pages, current_page) on public.books to authenticated;` (`books_update_own` still limits rows).
- Kept when the status changes (decision 0007); the app shows and edits them only while Reading, and `updateBookProgress` refuses otherwise.
- Trigger `books_finish_progress` (migration 4, `before update of status`, function `public.books_finish_progress()`, `security invoker`, `set search_path = ''`): when `new.status = 'finished'` and `old.status <> 'finished'` and `new.total_pages is not null`, sets `new.current_page = new.total_pages`. No progress → nothing changes. Runs next to `books_set_finished_on`; they set different columns, so order does not matter.

New table `public.shelves`:

| column | type | rules |
|---|---|---|
| `id` | `uuid` | `primary key default gen_random_uuid()` |
| `user_id` | `uuid` | `not null default auth.uid() references auth.users (id) on delete cascade` |
| `name` | `text` | `not null check (char_length(name) between 1 and 40)` |
| `created_at` | `timestamptz` | `not null default now()` |

- `create unique index shelves_user_id_lower_name_key on public.shelves (user_id, lower(name));`: one name per user ignoring case, race-free; also the index for listing one user's shelves. Two users may each have "Travel".
- `constraint shelves_id_user_id_key unique (id, user_id)` (migration 2), target of the composite foreign key.
- RLS enabled. Policies `to authenticated` on `(select auth.uid()) = user_id`: `shelves_select_own` (select), `shelves_insert_own` (insert, `with check`), `shelves_update_own` (update, `using` and `with check`), `shelves_delete_own` (delete).
- `revoke all on public.shelves from anon, authenticated; grant select, insert (name), update (name), delete on public.shelves to authenticated;`.
- The app trims names; the database stores what it is given within the length check.

New table `public.book_shelves` (a book on a shelf):

| column | type | rules |
|---|---|---|
| `book_id` | `uuid` | `not null` |
| `shelf_id` | `uuid` | `not null` |
| `user_id` | `uuid` | `not null default auth.uid()` |
| `created_at` | `timestamptz` | `not null default now()` |

- Primary key `(shelf_id, book_id)`: a book is on a shelf at most once; also the index for the shelf filter. `create index book_shelves_book_id_idx on public.book_shelves (book_id);` for a book's shelves.
- `foreign key (book_id, user_id) references public.books (id, user_id) on delete cascade` and `foreign key (shelf_id, user_id) references public.shelves (id, user_id) on delete cascade`: a link can only join a book and a shelf of the same owner (foreign key checks see every row, so this holds whatever RLS hides), and deleting a shelf or a book removes its links and nothing else. `user_id` cascades from `auth.users` through both.
- RLS enabled. Policies `to authenticated` on `(select auth.uid()) = user_id`: `book_shelves_select_own` (select), `book_shelves_insert_own` (insert, `with check`), `book_shelves_delete_own` (delete). No update.
- `revoke all on public.book_shelves from anon, authenticated; grant select, insert (book_id, shelf_id), delete on public.book_shelves to authenticated;`.

### Migrations
Each ends with `npm run db:types` and a commit of `lib/database.types.ts` when it changes tables or columns.
1. `<timestamp>_shelves.sql` (F028): `create table public.shelves (...)`, the unique index, enable RLS, the four policies, revoke/grant. `-- rollback: drop table public.shelves;`
2. `<timestamp>_book_shelves.sql` (F031): `alter table public.books add constraint books_id_user_id_key unique (id, user_id);`, `alter table public.shelves add constraint shelves_id_user_id_key unique (id, user_id);`, `create table public.book_shelves (...)`, its index, enable RLS, three policies, revoke/grant. `-- rollback: drop table public.book_shelves; alter table public.shelves drop constraint shelves_id_user_id_key; alter table public.books drop constraint books_id_user_id_key;`
3. `<timestamp>_book_reading_progress.sql` (F035): `alter table public.books add column total_pages smallint check (...), add column current_page smallint check (...), add constraint books_progress_pair check (...);`, the grant. `-- rollback: revoke update (total_pages, current_page) on public.books from authenticated; alter table public.books drop constraint books_progress_pair, drop column current_page, drop column total_pages;`
4. `<timestamp>_books_finish_progress.sql` (F038): the function and trigger. `-- rollback: drop trigger books_finish_progress on public.books; drop function public.books_finish_progress();` No type change.

All are additive (new tables, nullable columns, constraints that existing rows satisfy, a trigger): no feature needs a `needs_human` migration decision. Order: 1 before 2 (F031 depends on F028); 3 before 4 (F038 depends on F035); the shelf and progress chains are independent.

## Contract
Types live in `lib/` on top of `lib/database.types.ts`. Server actions follow M1–M3: `useActionState` with `(prev, formData)` (bound `(id, prev, formData)`), or a plain `(…, formData) => Promise<void>` form action for one-click buttons; each re-checks `requireUser()` and `isUuid` on every id it is given (bound arguments and form fields are client input). Database errors: queries throw; actions turn that into `formError: "Could not save. Try again."`.

`lib/shelves.ts` (new; pure parts with unit tests, queries with stub-client tests):
- `type Shelf = Pick<Tables<"shelves">, "id" | "name">`.
- `SHELF_NAME_TAKEN = "You already have a shelf with that name"`.
- `type ShelfFormState = FormState<"name"> & { saved?: true }`.
- `parseShelfName(formData): Parsed<string, "name">`: field `name`, trimmed; empty → "Name is required"; over 40 characters → "Name must be at most 40 characters".
- `listShelves(supabase): Promise<Shelf[]>`: own shelves (RLS), ordered by `name` (then `id`), so the list, picker and filter read the same.
- `insertShelf(supabase, name): Promise<"ok" | "taken">`: `"taken"` on Postgres `23505` (the unique index). `user_id` from the default.
- `updateShelfName(supabase, id, name): Promise<"ok" | "taken" | "missing">`: `.update({ name }).eq("id", id).select("id")`; no row → `"missing"`.
- `removeShelf(supabase, id): Promise<boolean>`: `.delete().eq("id", id).select("id")`.
- `listBookShelfIds(supabase, bookId): Promise<string[]>`: `shelf_id` of `book_shelves` with `book_id = bookId`.
- `listShelfBookIds(supabase, shelfId): Promise<string[]>`: `book_id` of `book_shelves` with `shelf_id = shelfId`.
- `type AddToShelfFormState = FormState<"shelf"> & { saved?: true }`.
- `parseShelfChoice(formData): Parsed<string, "shelf">`: field `shelf`, a UUID, else "Choose a shelf".
- `addBookToShelf(supabase, bookId, shelfId): Promise<"ok" | "missing">`: insert `{ book_id, shelf_id }`; `23505` (already on it) → `"ok"`; `23503` (book or shelf not the user's, or gone) or `42501` (RLS) → `"missing"`.
- `removeBookFromShelf(supabase, bookId, shelfId): Promise<void>`: `.delete().eq("book_id", bookId).eq("shelf_id", shelfId)`; removing a link that is not there is not an error.
- `parseShelfFilter(value: string | string[] | undefined, shelves: Shelf[]): string | undefined`: the value when it is the id of one of `shelves`, else `undefined` (unknown, malformed or another user's id → all books).
- `filterByShelf<T extends Book>(books: T[], bookIds?: string[]): T[]`: no `bookIds` → unchanged; else books whose id is in it, order kept.

`lib/books.ts` (changed):
- `ShelfBook` adds `"total_pages" | "current_page"`; `listBooks` adds both to its select (F037). `BookDetail` adds both; `getBook` selects them (F035). Signatures unchanged.
- `booksHref({ status?, q?, sort?, shelf? })`: parameters in the order `status`, `q`, `sort`, `shelf`, so M3's URLs are unchanged.
- `type ProgressFormState = FormState<"total_pages" | "current_page"> & { saved?: true }`.
- `parseProgress(formData): Parsed<{ totalPages: number; currentPage: number }, "total_pages" | "current_page">`: fields `total_pages`, `current_page`, trimmed, `/^\d+$/`. Total not 1 to 10,000 → `total_pages`: "Total pages must be a whole number from 1 to 10,000". Only with a valid total, current not 0 to total → `current_page`: "Current page must be a whole number from 0 to <total>" (`250` → "from 0 to 250"). Rejects empty, `0` total, `2.5`, `-1`.
- `updateBookProgress(supabase, id, { totalPages, currentPage }): Promise<boolean>`: `.update({ total_pages, current_page }).eq("id", id).eq("status", "reading").select("id")`; `false` when missing, someone else's or not Reading.
- `progressPercent(current: number, total: number): number`: `Math.round((current / total) * 100)` (100 of 250 → 40, 0 → 0, 250 of 250 → 100).
- `formatProgress(current, total): string`: `"Page 100 of 250 (40%)"`.

Server actions:
- `app/shelves/actions.ts` (new):
  - `createShelf(prev, formData): Promise<ShelfFormState>`: parse error → `{ fieldErrors, values: { name } }`; `"taken"` → `fieldErrors.name = SHELF_NAME_TAKEN` with the value kept; success → `revalidatePath("/shelves")`, `{ saved: true }` (the form clears).
  - `renameShelf(id, prev, formData): Promise<ShelfFormState>`: as `createShelf`; `!isUuid(id)` or `"missing"` → `formError: "Shelf not found"`; success also `revalidatePath("/books", "layout")`.
  - `deleteShelf(id, formData): Promise<void>`: `removeShelf` when `isUuid(id)`; `revalidatePath("/shelves")`, `revalidatePath("/books", "layout")`.
- `app/books/[id]/actions.ts` (added):
  - `addToShelf(bookId, prev, formData): Promise<AddToShelfFormState>`: parse error → `fieldErrors`; `!isUuid(bookId)` or `"missing"` → `formError: "Shelf not found"`; success → `revalidatePath("/books")`, `revalidatePath(`/books/${bookId}`)`, `{ saved: true }`.
  - `removeFromShelf(bookId, shelfId, formData): Promise<void>`: both bound; both `isUuid`, then `removeBookFromShelf`; same revalidation.
  - `saveProgress(id, prev, formData): Promise<ProgressFormState>`: parse error → `{ fieldErrors, values: { total_pages, current_page } }` (raw input kept, nothing saved); `!isUuid(id)` or `false` → `formError: "Book not found"`; success → revalidate `/books` and `/books/${id}`, `{ saved: true }`.

## Modules

- `lib/` must not import `app/` or `components/`.
- `components/` must not import `app/`, `lib/supabase/` or `@supabase/*`.

- No cycles. `lib/shelves.ts` may import `lib/books.ts` (`isUuid`, `Book`) and `lib/forms.ts`; `lib/books.ts` must not import `lib/shelves.ts` (the cycle rule enforces it).

## NFR
- Load: unchanged (tens of users, a few hundred books and a few dozen shelves each). `/books` adds one shelf list query, in parallel, and with a filter one primary-key-prefix lookup on `book_shelves`; filtering stays in memory. `/books/[id]` adds two small queries in parallel. No new public page.
- Security: threats are reading or changing another user's shelves, linking my book to another user's shelf (or theirs to mine), forging `user_id`, and probing ids through `?shelf=` or bound ids. Owner RLS on both new tables; column grants leave `user_id` to the default; the composite foreign keys make a cross-owner link impossible even if a policy were wrong; foreign ids give "missing"/"not found", never a different error. `?shelf=` is used only when it is one of the user's own shelf ids, otherwise ignored. Progress goes through `books_update_own`, the column grant and the checks; only Reading books are updated.
- Cost: unchanged: local Docker, free-tier Supabase branch and Vercel preview.

## Decisions
- **Composite foreign keys `(book_id, user_id)` and `(shelf_id, user_id)`** to guarantee a link's book and shelf share its owner. Rejected: an insert policy with `exists` subqueries on `books` and `shelves` (works, but correctness then rests on RLS of three tables; FKs are checked on every row regardless). Costs two additive unique constraints.
- **Case-insensitive uniqueness by a unique index on `lower(name)`** and mapping `23505` to the field error. Rejected: a pre-insert lookup in the app (racy, second query) and `citext` (an extension for one column).
- **Cascade on shelf delete** removes only links, so "deleting a shelf keeps its books" holds in the schema.
- **Shelf filter by an id list plus in-memory filter**, like search and sort in M3: `listBooks` keeps its signature, and the shelf id from the URL is checked against the user's own shelves before it reaches a query. Rejected: an `!inner` embedded filter in `listBooks` (changes its signature and every test).
- **Progress as two nullable columns on `books`** with a pair check, not a table: one value per book, no history in scope.
- **Finishing copies the total in a trigger** (`books_finish_progress`), next to M2's finish-date trigger, so every status path (form, future ones) does it in the same statement. Rejected: doing it in `updateBookStatus` (a second write, or an update that needs the total first).
- **`booksHref` appends `shelf` last**, so M3 links and tests keep their URLs.

No earlier design or decision changes; M4's product choices are in decision 0007.

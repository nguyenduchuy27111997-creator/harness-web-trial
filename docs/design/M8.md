## Data model
Every M1–M7 table and policy stays; RLS on `books`, `notes`, `quotes`, `tags`, `book_tags`, `shelves`, `book_shelves` is unchanged (F083).

`public.books` gains:
| column | type | rules |
|---|---|---|
| `cover_path` | `text` | null; `check books_cover_path_own (cover_path is null or (char_length(cover_path) <= 200 and starts_with(cover_path, user_id::text \|\| '/' \|\| id::text \|\| '-')))`; grant `update (cover_path)` to `authenticated` |
- The check means a book can only point at an object in its owner's folder named after that book, so no one can make `cover_is_shared` (below) return true for another user's file.

Storage bucket `covers` (row in `storage.buckets`): `public = false`, `file_size_limit = 2097152`, `allowed_mime_types = {image/jpeg,image/png,image/webp}`. Object name `<user_id>/<book_id>-<uuid>.<jpg|png|webp>`; a replace writes a new name, then deletes the old object. Policies on `storage.objects`:
- `covers_owner_select`, `covers_owner_update`, `covers_owner_delete` `to authenticated`: `bucket_id = 'covers' and (storage.foldername(name))[1] = (select auth.uid())::text`.
- `covers_owner_insert` `to authenticated`: the same, and `exists` a book of `auth.uid()` whose `id || '-'` starts `storage.filename(name)`.
- `covers_anon_sign_shared` `for select to anon`: `bucket_id = 'covers' and storage.allow_any_operation(array['object.sign','object.sign_many']) and public.cover_is_shared(name)`. Operation names confirmed in the local storage image `storage-api:v1.79.28` (`dist/http/routes/operations.js`: `SIGN_OBJECT_URL: "storage.object.sign"`, `SIGN_OBJECT_URLS: "storage.object.sign_many"`; listing is `storage.object.list`, downloads `storage.object.get_authenticated`); `storage.allow_any_operation(text[])` exists in the local database and strips the `storage.` prefix before comparing. So anon may sign a shared cover and nothing else: list, download by path, upload and delete match no anon policy.
- Storage blocks SQL deletes on `storage.objects` (trigger `protect_objects_delete`), so files are removed through the Storage API by the app, never by a cascade.

`public.shelf_shares`:
| column | type | rules |
|---|---|---|
| `shelf_id` | `uuid` | `primary key` (one live link per shelf) |
| `user_id` | `uuid` | `not null default auth.uid() references auth.users (id) on delete cascade` |
| `token` | `text` | `not null unique default encode(extensions.gen_random_bytes(24), 'hex')` (48 hex characters, 192 random bits) |
| `created_at` | `timestamptz` | `not null default now()` |
- `foreign key (shelf_id, user_id) references public.shelves (id, user_id) on delete cascade` (deleting the shelf ends the link).
- RLS on; policies `shelf_shares_select_own`, `shelf_shares_insert_own`, `shelf_shares_delete_own` `to authenticated` on `(select auth.uid()) = user_id`; no update. `revoke all ... from anon, authenticated`; grants `select, insert (shelf_id), delete` to `authenticated`. Stop sharing deletes the row; Share again inserts a new one with a new token. `anon` has no grant on the table.

Functions:
- `public.shared_shelf(p_token text) returns table (shelf_name text, book_id uuid, title text, author text, status text, rating smallint, cover_path text, added_at timestamptz)`, `stable security definer set search_path = ''`. Joins `shelf_shares` → `shelves` → `book_shelves` → `books` (left joins, `b.user_id = s.user_id`) on `token = p_token`: one row per book (newest added first), one row with null book columns for an empty shelf, no rows for an unknown or revoked token. Returns no notes, quotes, review, tags, other shelves, email, display name or user id. `revoke execute ... from public`; `grant execute ... to anon, authenticated`.
- `public.cover_is_shared(p_name text) returns boolean`, `stable security definer set search_path = ''`: a book whose `cover_path = p_name` is on a shelf that has a `shelf_shares` row. Execute granted to `anon` only (it is used by `covers_anon_sign_shared`).
- `public.books_broadcast()` trigger, `security definer set search_path = ''` (`realtime.send` is not security definer and `authenticated` cannot insert into `realtime.messages`): `realtime.broadcast_changes('books:' || coalesce(new.user_id, old.user_id)::text, tg_op, tg_op, tg_table_name, tg_table_schema, new, old)`. `after insert or update or delete on public.books for each row`. Execute revoked from `public, anon, authenticated`. `broadcast_changes` sends private messages (`realtime.send` default `private = true`), which only private channels receive.

Realtime: policy `books_topic_owner_receives on realtime.messages for select to authenticated using (realtime.messages.extension = 'broadcast' and (select realtime.topic()) = 'books:' || (select auth.uid())::text)`. Realtime checks it when a private channel joins: only the owner can join `books:<their id>`, so every insert, update and delete message of A's books, including a delete's `old` row, goes only to A's tabs. `books` is not added to the `supabase_realtime` publication (no `postgres_changes`).

## Contract
Types live in the `lib/` module named; tables are read through `lib/database.types.ts`.

Lookup (F079, F080):
- `type LookupBook = { title: string; author: string; totalPages: number | null }`; `type LookupResult = { status: "found"; book: LookupBook } | { status: "not_found" } | { status: "timeout" } | { status: "unavailable" }` in `lib/lookup.ts`.
- `parseLookupQuery(raw: unknown): { kind: "isbn" | "title"; key: string } | null`: trimmed, 1–200 characters; ISBN-10/13 with hyphens or spaces removed → `isbn`, else `title` (key lower-cased).
- `createLookup({ fetch, now })` returns `lookupBook(query)` with its own cache: `Map` of key → `{ result, at }`, a hit within 24 h returns without fetching; only `found` and `not_found` are cached. Calls `https://openlibrary.org/isbn/<isbn>.json` (+ the author from `/authors/<key>.json`) or `https://openlibrary.org/search.json?title=<t>&limit=1&fields=title,author_name,number_of_pages_median`, with `AbortSignal.timeout(5000)` → `timeout`; 404 or no doc → `not_found`; 429 or 5xx or network error → `unavailable`. `lookupBook` is the module's instance with the global `fetch`. Unit test with a fake fetch: same ISBN twice → one call; after 24 h → two.
- `lookupFromFixture(path: string, query): Promise<LookupResult>` in `lib/lookup-fixture.ts`: reads the JSON file at `path` (`Record<string, LookupResult>` keyed by `parseLookupQuery(...).key`), missing key → `not_found`. `e2e/fixtures/lookup.json` holds found ISBN and title entries and one query each for `timeout` and `unavailable`.
- `GET /api/lookup?q=<query>` (`app/api/lookup/route.ts`): no signed-in user → 401 `{ error: "Sign in" }`; bad query → 400 `{ error: "Enter an ISBN or a title" }`; else 200 `LookupResult`, from `lookupFromFixture(process.env.BOOK_LOOKUP_FIXTURE, q)` when that variable is non-empty, otherwise `lookupBook(q)`. The browser only calls this route. `playwright.config.ts` sets `BOOK_LOOKUP_FIXTURE ??= "e2e/fixtures/lookup.json"` before `webServer`; `init.sh` exports `BOOK_LOOKUP_FIXTURE="${BOOK_LOOKUP_FIXTURE-e2e/fixtures/lookup.json}"` (an owner can run `BOOK_LOOKUP_FIXTURE= ./init.sh` to use Open Library). Messages: `timeout` "Lookup timed out, enter the book by hand"; `not_found` "No book found for <query>"; `unavailable` "Lookup is not available right now". The fields stay editable in every case.

Covers (F081, F082):
- `COVER_TYPES = { "image/jpeg": "jpg", "image/png": "png", "image/webp": "webp" }`, `COVER_MAX_BYTES = 2 * 1024 * 1024`; `parseCoverFile(value: FormDataEntryValue | null): { file: File; ext: string } | { error: string }`: refuses an empty, over-size or other-type file with "Use a JPEG, PNG or WebP image up to 2 MB" (the bucket's size and type limits refuse it again). `components/cover-form.tsx` (client) runs the same size and type check on the chosen file with `COVER_MAX_BYTES` and `COVER_TYPES` (pure constants from `lib/covers.ts`, which imports Supabase only as types) and, on failure, shows that message and does not submit, so a file over the 3 MB action body limit never reaches Next; the input has `accept="image/jpeg,image/png,image/webp"`. The F081 e2e tests a file between 2 and 3 MB and one over 3 MB.
- `coverPath(userId, bookId, ext)` → `<userId>/<bookId>-<randomUUID>.<ext>`.
- `uploadCover(supabase, userId, bookId, file, ext): Promise<boolean>`: reads the book (RLS; false if none), uploads, sets `cover_path`, then removes the old object; on a failed update removes the new one.
- `removeCover(supabase, bookId): Promise<boolean>`: clears `cover_path`, removes the object.
- `removeAllCovers(supabase, userId)`: lists `covers/<userId>` in pages of 100 and removes them; `deleteAccount` calls it before `rpc("delete_account")`. `removeBook` reads `cover_path` and removes the object after the row is deleted.
- `signCovers(supabase, paths: string[]): Promise<Map<string, string>>`: one `createSignedUrls(paths, 600)`; a path that fails is left out (placeholder shown). Never `getPublicUrl`.
- Actions in `app/books/[id]/actions.ts`: `uploadCoverAction(bookId, prev, formData)` and `removeCoverAction(bookId)`, bound id checked with `isUuid`, `requireUser()`, then `revalidatePath`. Form state `{ error?: string }`.
- `BookCover({ title, url, size: "sm" | "lg" })`: an `img` of fixed width and height (`sm` 40×60 for the list, `lg` 128×192 for the book page) with `alt="Cover of <title>"`, or a same-size box with the title's first letter.

Sharing (F083, F084):
- `listShares(supabase): Promise<Map<string, string>>` (shelf id → token, one query for `/shelves`), `shareShelf(supabase, shelfId): Promise<string | null>` (insert, return token; an existing row returns its token), `stopSharing(supabase, shelfId): Promise<void>`.
- `getSharedShelf(supabase, token): Promise<SharedShelf | null>` where `SharedBook = { id: string; title: string; author: string; status: BookStatus; rating: number | null; coverPath: string | null }`, `SharedShelf = { name: string; books: SharedBook[] }`. A token that is not 48 lower-case hex characters returns null without a query. The generated type for `shared_shelf` marks every column non-null, which is wrong for `rating`, `cover_path` and, for an empty shelf, the book columns, so `lib/share.ts` declares `SharedShelfRow` with `book_id`, `title`, `author`, `status`, `rating`, `cover_path` and `added_at` as `| null` and calls `supabase.rpc("shared_shelf", { p_token: token }).overrideTypes<SharedShelfRow[], { merge: false }>()`; no rows → null; rows with `book_id === null` are skipped.
- `createAnonClient(): SupabaseClient<Database>` in `lib/supabase/server.ts`: `createClient` from `@supabase/supabase-js` with the anon key and `persistSession: false`, no cookies. `/s/[token]` uses it for `getSharedShelf` and `signCovers`, so a signed-in visitor reads the page with the same anon rights as anyone.
- Actions in `app/shelves/actions.ts`: `shareShelfAction(shelfId)`, `stopSharingAction(shelfId)` (`isUuid`, `requireUser()`, `revalidatePath("/shelves")`). The link shown is `${origin}/s/<token>` from the request headers; "Copy link" uses `navigator.clipboard`.
- `/s/[token]`: heading = shelf name, each book's cover, title, author, `StatusBadge`, rating; no links to `/books/...`, no forms; `generateMetadata` title "<shelf name> · Bookshelf"; `notFound()` when `getSharedShelf` is null. `SiteHeader` is unchanged: a signed-out visitor sees the signed-out header (no links to anyone's pages); a signed-in visitor sees their own normal header (the acceptance covers signed out only).

Paging (F085):
- `PAGE_SIZE = 20`; `parseLimit(raw): number`: a multiple of 20 from 20 to 1000, else 20. `pageBooks<T>(books: T[], limit): { books: T[]; hasMore: boolean }` slices the filtered, sorted list. `/books` still loads every book (counts come from all of them), then filters, sorts and pages; covers are signed for the visible page only. `booksHref` gains `limit` (omitted at 20); tab, search, sort, shelf and tag links reset it. `LoadMore({ href })` is a `Link` to the same query with `limit + 20`, shown while `hasMore`. A new book is one row in the re-sorted list, so it shows once.

Live list (F086):
- `lib/supabase/client.ts`: `createClient()` with `createBrowserClient<Database>` from `@supabase/ssr` (the anon key and the session cookies).
- `subscribeToBooks(supabase, userId, onChange: () => void, onReconnect: () => void): () => void` in `lib/realtime.ts`: `await supabase.realtime.setAuth()`, then `supabase.channel("books:" + userId, { config: { private: true } }).on("broadcast", { event: "*" }, onChange).subscribe(status => ...)`; a `SUBSCRIBED` after `CHANNEL_ERROR`, `TIMED_OUT` or `CLOSED` calls `onReconnect`. Returns an unsubscribe (`removeChannel`). Unit-tested with a fake channel.
- `LiveRefresh({ userId })` in `app/books/live-refresh.tsx`: subscribes on mount, calls `router.refresh()` 500 ms after the last `onChange` of a burst (a trailing debounce, so the last event of a burst is never dropped), and once for `onReconnect` (catch up). Renders nothing. Every message it can receive is one of the user's own books (policy `books_topic_owner_receives`), so it needs no filtering.

## NFR
- Load: unchanged (tens of users, a few hundred books each). `/books` keeps one `listBooks` query and adds one `createSignedUrls` call for at most `limit` covers. Lookup: one or two Open Library requests per uncached query, 5 s timeout, cached a day per server process (in memory; at this load a shared cache is not needed). Covers ≤ 2 MB each. Realtime: one channel per open `/books` tab; an import of up to 1,000 books sends up to 1,000 messages, collapsed by the 500 ms trailing debounce. `/s/[token]` is one `rpc` and one signing call; it is not in `lighthouserc.cjs` (a static URL list cannot hold a live share token, so Lighthouse would only measure the not-found page).
- Security: threats are reading another user's books, covers or shelves through ids, paths, tokens or Realtime; guessing a share token; a shared page leaking private fields; using the lookup route as an open proxy.
  - Shelf data for anonymous visitors only through `shared_shelf` (security definer, fixed columns, exact token match); `anon` has no grant on `shelf_shares`, and RLS and grants on `books`, `notes`, `quotes`, `tags` and the rest are unchanged, so an anon `select` on them returns nothing. Tokens carry 192 random bits (`gen_random_bytes(24)`); Stop sharing deletes the row, so `shared_shelf` returns no rows and the page is not found at once.
  - Covers: the bucket is private (`public = false`); owner policies `covers_owner_*` limit an authenticated user to their own folder, so B's download, sign, list, upload or delete under A's folder fails; `books_cover_path_own` stops a book from pointing at someone else's file; anon may only run `object.sign`/`object.sign_many` on a shared book's current cover (`covers_anon_sign_shared`), so anon `list('')` and `list('<owner id>')` on `covers` return nothing and a direct anon download fails. A signed URL is valid for 600 s and storage does not revoke it: a shared cover stays readable through a URL already issued for up to 10 minutes after Stop sharing or after the book leaves the shelf; replacing or removing the cover deletes the object, so its old URLs stop working. A signed URL shows the owner's user id in its path (not their email or name).
  - Realtime: `books_broadcast` sends each change only on `books:<owner id>` as a private message, and `books_topic_owner_receives` lets only that owner join the topic, so B's tab gets no message, not even a delete id, for A's books, and B joining `books:<A id>` is refused.
  - Lookup: the route requires a signed-in user and only calls two fixed Open Library URLs with the query encoded.
  - F084 checks (anon key, local stack): `shared_shelf` with a made-up and with a revoked token returns `[]`; anon `select` on `books`, `notes`, `quotes`, `shelves`, `shelf_shares`, `book_shelves` returns `[]`; anon `list('')` and `list('<owner id>')` on `covers` return `[]`; anon `createSignedUrl` for a cover of a book not on a shared shelf fails; for one on a shared shelf it succeeds.
  - F087 checks: B's `createSignedUrl` and `download` of A's cover path fail; a URL A signed with `expiresIn: 1` fails after 2 s, and A's URL for a removed cover fails; B subscribed to `books:<B id>` receives nothing while A adds, edits and deletes a book, and B's private channel `books:<A id>` never reaches `SUBSCRIBED`; `/s/<made-up token>` is not found; after A stops sharing, B and a signed-out visitor get not found on the old link.
- Cost: unchanged: local Docker, free-tier Supabase (Storage and Realtime included) and Vercel preview; Open Library is free and is called only outside tests.

## Decisions
- **Realtime by `realtime.broadcast_changes` on a private `books:<user_id>` topic with an RLS policy on `realtime.messages`**, so the owner alone receives every event, deletes included. Rejected: `postgres_changes` on `books` (Supabase cannot apply RLS or a filter to delete events, so a delete's primary key would reach every subscriber, against F086 and F087).
- **Refresh the server render on an event** (`router.refresh()`), not patching the list in the browser, so filters, sort, paging, counts and covers stay computed in one place.
- **The shared, anonymous read path is one security definer function**, and anon signing of covers is a storage policy limited to the sign operations and to shared covers. Rejected: a service-role key in the app server to sign covers (a far stronger secret), public URLs (spec forbids).
- **One link per shelf, the row deleted on Stop sharing** (primary key `shelf_id`), so a new share always has a new token. Rejected: a `revoked_at` column (more states, same behaviour).
- **The share page uses a cookieless anon client**, so a signed-in visitor sees exactly what a signed-out one does, and the anon storage policy applies to both.
- **Paging slices the in-memory list** that `/books` already loads (counts and filters need all books), with `?limit=` in the URL. Rejected: `range()` queries (would split the counts and the M3/M7 filters into separate queries).
- **Cover object names carry a random part**, so a replace makes a new object and old signed URLs end with the old object.
- **Covers removed by the app through the Storage API** before an account delete and after a book delete, because storage forbids SQL deletes on `storage.objects`.
- **The lookup cache is in memory per server process.** Rejected: a database table (a migration and RLS for data that is fine to lose).
- **`serverActions.bodySizeLimit` goes from `"2mb"` to `"3mb"`** so a 2 MB image plus the form encoding fits; the import's own 1 MB check (M7) is unchanged.

The body size change is recorded in `docs/decisions/0020-cover-body-size-limit.md`; no other earlier design or decision changes.

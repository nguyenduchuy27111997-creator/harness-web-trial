# Release M2

- Date: 2026-11-04
- Tag: `M2-rc` (first release tag; M1 was never tagged, so this release covers M1 + M2)
- Features: F001–F016, all `passing`; release regression run by the `verifier` on every one.

## What users can do
M1
- Sign up with email and password (F001)
- Sign in and sign out from the header (F002)
- Signed-out visitors are sent to sign in (F003)
- See an empty shelf on /books (F004)
- Add a book (F005), with validation errors next to the field (F006)
- See the list newest first with status badges (F007)
- See only their own books (F008)

M2
- Open a book page at /books/<id> (F009)
- Change a book's status; finishing records today's date (F010)
- Rate a finished book 1 to 5 stars (F011)
- Write a short review of a finished book (F012)
- Filter the list by status with tabs kept in the URL (F013)
- Delete a book after confirming (F014)
- See stats: finished this year and average rating (F015)
- Get a "Book not found" page (HTTP 404) for missing or other users' books (F016)

## Known limitations
- Finish dates and "this year" use UTC, not the user's time zone (decision 0002).
- Moving a book back to Finished re-shows its earlier rating and review (decision 0002).
- No password reset, email confirmation, social login, profile page or account deletion (out of scope per spec).
- A signed-in user who opens /sign-in or /sign-up sees the form instead of being redirected to /books.
- Keyboard: pressing ArrowRight on the checked star rating did not move the selection in the release check (not investigated).
- Worth a designer contrast check: the "Finished" badge text looked pale on its green background in the release screenshots.
- Cosmetic: the Stats header link has no current-page highlight; the not-found page keeps the tab title "Book · Bookshelf".
- Through the Supabase REST API a user can set `rating`/`review` on their own book that is not Finished (it is hidden in the UI until Finished). This affects only the user's own data.

## Blocked or deferred
- None in the backlog.
- Staging deploy not run: `scripts/deploy-staging.sh` needs `SUPABASE_PROJECT_REF`, `VERCEL_TOKEN`, `VERCEL_ORG_ID` and `VERCEL_PROJECT_ID`, which are not set in this environment.

## Security notes
- Whole-repo review (no earlier tag): no high or medium findings.
- `public.books` has RLS on for select, insert, update and delete, each limited to `auth.uid() = user_id`. Only `status`, `rating` and `review` can be updated, so a book cannot be moved to another user. There are no SECURITY DEFINER functions. The trigger sets `search_path = ''`.
- Every server action calls `requireUser()` (`getUser()`) and uses the cookie-scoped anon client. No service_role key is used in app code.
- No `dangerouslySetInnerHTML`. Redirects go only to fixed paths.
- Before production, check that email confirmation is enabled or deliberately disabled on the hosted Supabase project. Local `supabase/config.toml` has `enable_confirmations = false`, as the spec asks.

# Release M3

- Date: 2026-11-05
- Tag: `M3-rc` (changes since `M2-rc`)
- Features: F018–F024, all `passing`. In the release regression run, the `verifier` checked every feature from M1–M3 (F001–F024), and all 24 passed.

## What users can do
M3
- Edit a book's title and author from its page (F018), with validation errors next to the field (F019)
- Search the shelf by title or author, kept in the URL (F020)
- When a search has no matches, get a link to clear the search (F021)
- Sort the list by newest, title or rating, kept in the URL (F022)
- Set a reading goal for this year on Stats (F023) and change it later (F024)

M1 and M2 features are unchanged (see `docs/releases/M2.md`). F017 also fixes an M2 limitation: signed-in users who open /sign-in or /sign-up are now sent to /books.

## Known limitations
Verifiers reproduced each of these during this release run:
- Accessibility: after moving between pages inside the app, earlier pages stay in the DOM, hidden. As a result there can be two `<main>` elements, and duplicate `id="email"` and `id="password"` inputs, after signing up or signing out (F002, F007). The accessibility tree also names fields twice: "Status Status" on the book page, and "Title Title" and "Author Author" in the edit form (F010, F018). Screen readers may read these labels twice. A fresh page load does not show the duplicates on the auth pages.
- Accessibility: while the edit form is open, a book page has two buttons named "Save", one for title and author and one for status (F018).
- Stats: once "Change goal" is open there is no Cancel button. The only way out is to save or reload the page (F024).
- Carried over from M2, by design (decision 0002): finish dates and "this year" use UTC. Moving a book back to Finished shows its earlier rating and review again.
- Out of scope per the spec: password reset, email confirmation, social login, profile page and account deletion.

Carried over from M2 and not re-checked in this run: arrow keys on the star rating, contrast of the "Finished" badge, no current-page highlight on the Stats link, the tab title on the not-found page, and setting `rating`/`review` through the REST API on one's own unfinished book.

## Security notes
- I reviewed `git diff M2-rc..HEAD` and found no high or medium findings.
- `public.reading_goals`: RLS is on, with select, insert and update each limited to `auth.uid() = user_id` (update has both `USING` and `WITH CHECK`). There is no delete policy or grant. `user_id` defaults to `auth.uid()`, and only `year` and `goal` are granted for insert and update.
- `public.books`: the new column grant adds `update (title, author)` only. `user_id`, `finished_on` and the other columns stay non-updatable. The existing RLS update policy still applies, so editing another user's book id matches 0 rows and the action returns "Book not found".
- Search `q` and `sort` never reach PostgREST. Filtering and sorting run in memory over the user's own rows, and `sort` is allowlisted, so filter injection is not possible.
- The new server actions (`editBook`, `saveGoal`) call `requireUser()` and take no user ids from the client. The goal year comes from the server clock.
- There is no `dangerouslySetInnerHTML`. Search terms are rendered as escaped text; the verifier checked this with an HTML payload.
